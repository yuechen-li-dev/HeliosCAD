# SolidWorks part bridge

Date: 2026-11-02

## Result

The native one-button path is qualified on SolidWorks 2026 SP4.0 (API 34.4.0):
clicking **Aetheris Helios → Export to Aetheris Helios** on the separate test part
exports ordinary AP214, canonicalizes through Aetheris, and opens a Ready Helios
workspace through the one-use loopback handoff. The three browser cases pass
against the exact archive generated by this native click: attached datum and
bilateral diameter allowance authoring, semantic AP242/annotated GLB export and
workspace reopen; remote handoff rejection; and changed-asset refusal.

The resulting enriched AP242 was independently reimported into SolidWorks as
one solid body, volume 10602.87520586555 mm³, with zero warnings. The local
COM/MCP creation, guarded dimension edit, rebuild and export path is also qualified.
Scope remains single-solid parts and the existing datum/diameter authoring slice.

## Native registration failure and resolution

The first machine installer wrote discovery but omitted managed COM registration.
Current-user COM activation and QueryInterface for ISwAddin worked, yet native
loading returned zero without a connected object. File → Open reported "Unable
to initialize the Add-In component" before our constructor/ConnectToSW ran.
SolidWorksPerformance.log classified Helios as `COM.old` with no title; working
vendor managed add-ins were `NET` and had machine COM metadata.

Build 0.1.7 registers this add-in's managed CLSID/ProgID under HKLM Software/Classes
as well as its SolidWorks discovery entry. The user ran the corrected command as
administrator. Both entries and their exact CodeBase paths now match the build.
Loading succeeded in the original running session: ConnectToSW cookie 21,
GetAddInObject non-null, loadResult 0/connected true. A repeat load returned
loadResult 2/connected true. A restart was not required; the earlier discovery-cache
hypothesis was not the cause. The CLI checks actual connection rather than
mistaking a zero loader status for success, and --registration-status diagnoses
machine/user registration without requiring a SolidWorks connection.

An attempted separate session required vendor sign-in and produced the concurrent
journal warning. No journals or vendor settings were changed. The original
unsaved user document remains open and untouched. No startup task, installed
service or add-in autoload entry was installed.

The installed build is `artifacts/local/solidworks/addin-0.1.7/`, configured for
local Helios at http://127.0.0.1:4175. The build script supports -OutputDirectory
for staging updates separately from DLLs retained by a running SolidWorks process.
The final build passes with zero warnings/errors. Only the add-in is COM-visible;
it implements the vendor ISwAddin contract with dispatch callbacks. Connection
logging is best-effort so a log-write failure cannot mask the original problem.
## Implementation

- `src/solidworks/`: .NET Framework 4.8 x64 add-in and stdio MCP/CLI. The command
  exports one solid body through SolidWorks' ordinary `SaveAs` AP214 route,
  restoring the protocol and solid/surface export preferences afterward. A
  suspended temporary selection list exports the complete part and reinstates
  the user's original selection.
- The existing Aetheris `canon` importer owns admission and conversion. The
  original vendor file is retained byte for byte; there is no header rewriting,
  native-file reverse engineering or secondary geometry implementation.
- Each export creates a new directory, a canonical STEP with a SHA-256 pin,
  a Firmament annotation root and a `.helios.zip` workspace. A one-use,
  origin-checked loopback transfer opens `/solidworks`. It expires in two minutes
  and has no modeling command endpoint. A saved workspace is the recovery path.
- The five MCP tools inspect, create a separate simple extruded part, edit an
  existing linear dimension, rebuild, and export. Native edits require the
  inspected document/configuration token and expected old value. No arbitrary
  script evaluation, shell tool, native-file overwrite or model-upload path.
- Helios previously left imported PMI buttons disabled in Source view because
  the compiler outline was only fetched in Graph view. Imported PMI now gets a
  current compiler outline in either view; stale outlines cannot author edits.
- Build/setup and limits are in `docs/public/solidworks.md`. Client-specific
  transmission of MCP results is explicitly distinguished from this local bridge.

## Real qualification

SolidWorks Design Professional for Makers 2026 SP4.0, API revision 34.4.0,
was already running. Its original unsaved showcase part was preserved. All new
modeling work used separate test documents. No MBD API was invoked.

`scripts/qualify-solidworks.mjs` uses actual JSON-RPC over the compiled stdio
client: inspect → new 40/10 mm annulus → refuse stale document and stale value →
edit extrusion 8→9 mm → rebuild → export. SolidWorks mass properties independently
match `π × (20² − 5²) × 9 = 10602.875205865551 mm³`. Export preference values before
and after match. The resulting raw file declares `AUTOMOTIVE_DESIGN` / STEP AP214.
A selected-face export was also exercised manually: selected-object count was
preserved and the complete result reimported into SolidWorks with the same volume.

The enriched AP242 was also independently imported back into SolidWorks through
its documented foreign-file `LoadFile4` path. SolidWorks returned one solid body,
no warnings, and volume `10602.875205865552 mm³`. The probe closes only its newly
imported test document without saving. An initial `OpenDoc6` probe returned
`swFileRequiresRepairError` (2097152); using the actual STEP import API resolved
that entry-point error. This verifies geometry interchange, not SolidWorks PMI
display or full external semantic conformance.

The browser receives the real generated workspace, picks a planar datum A and
the 10 mm bore, and authors +0.02/−0.01 mm allowances through the UI. AP242 export
contains standard dimensional-size and bilateral-tolerance entities. CLI semantic
reinspection finds one datum, one dimension, exact nominal/allowances, and distinct
associated geometry. Geometry remains one enclosed manifold body. GLB contains
the same named requirement and allowances. Saved workspaces retain both original
and canonical STEP assets byte for byte and reopen with annotations. An altered
asset is refused with `firmament-inline-step-source-pin-mismatch`, retaining the
last valid model instead of reusing attachments.

The installed browser SDK was older than the current kernel source and initially
emitted only the earlier bounded PMI representation. The generated development
SDK and CLI were rebuilt from the current sibling checkout; standard AP242 size
and tolerance entities now come from the existing kernel exporter. No Aetheris
kernel source changes were made. The old CLI initially counted the new standard
mirror as a second dimension; rebuilding the CLI aligned semantic inspection.
